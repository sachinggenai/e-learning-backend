# E-Learning Platform — Project Summary

Date: 2026-06-07

## Project Overview

This repository implements a full-stack e-learning platform combining a React + TypeScript frontend (authoring + preview) with a Python FastAPI backend that manages course persistence, template-driven content, SCORM export, media uploads, scoring/completion tracking, and analytics.

## Frontend Summary

The frontend is a Create React App (CRA) application using React 18 and TypeScript. It provides a dynamic authoring/editor and preview shell driven by a runtime component/template registry, supports drag-and-drop authoring, schema validation, and integrates with backend APIs to manage course content, templates, media, and exports.

## Frontend Technology Stack

- React 18 + TypeScript
- Create React App (`react-scripts` 5.0.1)
- Redux Toolkit + react-redux
- Axios (service layer `httpClient.ts` / `api.ts`) with base `REACT_APP_API_BASE || /api/v1`
- `@hello-pangea/dnd` for drag-and-drop
- `lucide-react` for icons
- `ajv` for JSON schema validation
- `uuid` / `nanoid` utilities
- ESLint, Prettier, TypeScript type-checking
- Jest + React Testing Library (unit tests)
- Playwright (end-to-end)

## Frontend Architecture (high-level)

- App entry: `src/index.tsx` renders `<App />` inside Redux provider and global CSS.
- Root shell: `src/App.tsx` wraps theme and toast providers, bootstraps registry and template styles, checks backend health, and switches editor/preview flows.
- State: Redux Toolkit store under `src/store`, slices, adapters, typed hooks.
- Services: Axios client in `src/services/httpClient.ts` and `api.ts` with base URL convention `/api/v1`.
- Components: `src/components` houses editor, preview, header, menu, registry, templates, error boundary, and toasts.
- Registry: Dynamic component/template registry under `src/components/registry` supporting runtime lookup and rendering.

## Backend Summary

The backend is a FastAPI application exposing REST endpoints mounted under `/api/v1`. It handles import/export workflows, template definitions, media uploads, export generation (SCORM), scoring/completion persistence, and repository/service layers for business logic.

## Backend Technology Stack

- Python 3.x + FastAPI
- Uvicorn ASGI server
- SQLAlchemy async ORM
- PostgreSQL (production target) via `postgresql+asyncpg://...`
- Alembic for migrations
- Async DB sessions, repositories, service layers

Key config and references:
- Database configuration and async session factory: [app/db/config.py](app/db/config.py)
- Alembic config: `alembic.ini` (points to a PostgreSQL URL)

## Backend Architecture (high-level)

- Routers: structured routers for courses, templates, media, export, scoring, registry/theme, and completion.
- Services: business logic and export/SCORM renderers under `app/services` and `app/services/scorm`.
- Repositories: data persistence using SQLAlchemy models in `app/models` and repo modules in `app/repositories`.

## Full System Integration

- Frontend base API: `REACT_APP_API_BASE || /api/v1` (frontend uses axios client and sends requests relative to this base).
- Backend endpoints are mounted under `/api/v1`.
- Frontend calls backend for course/page/component/registry/media/export/scoring operations.
- Database: PostgreSQL in production; tests use SQLite (`sqlite+aiosqlite`) in some test configs.

## Deployment and Environment

- Frontend: CRA build output (`./build`) is a static site; `render.yaml` contains static deployment configuration for Render. Use `npm run build` to produce `./build`.
- Backend: FastAPI server run with Uvicorn; environment variables such as `DATABASE_URL` determine DB connectivity.

- PostgreSQL-backed async ORM with Alembic migrations
